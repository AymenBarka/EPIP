# Release v1.4.0

## Highlights and modules

Added EPIP-014 Execution Engine as the sole order-execution and broker boundary. It introduced
`ExecutionSnapshot`, order/fill management, explicit lifecycle, adapter protocol, paper adapter,
MT5 stub, retry, slippage, commissions, graph, history, events, and serialization.

## Architecture changes

Execution consumes only accepted `PositionPlan` objects and never decides or sizes trades. Broker
communication is isolated behind `BrokerAdapterProtocol`; future Portfolio and AI modules consume
only immutable execution outcomes.

## Quality and tests

Black, Ruff, strict MyPy, and Pytest passed. The reference validation ran 205 tests with 97%
aggregate coverage. Tests covered lifecycle, illegal transitions, paper/broker protocols, retry,
slippage, commission, Risk integration, events, history, graph, and serialization.

## Benchmarks

Reference local runs measured 100k order constructions in approximately 0.236 s and 1M in
approximately 2.491 s: about 402k–424k orders/s with roughly 2.36–2.49 µs average latency. Memory
figures were estimates rather than RSS measurements.
